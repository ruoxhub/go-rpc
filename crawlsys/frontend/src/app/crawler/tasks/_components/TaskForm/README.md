# TaskForm

任务新建与编辑表单的客户端编排入口。负责平台和接口选择、元数据联动、受控数据源状态、提交反馈及任务 DTO 组装，不承载任务列表或操作按钮逻辑。

## 内部文件

- `index.tsx`：组合表单区块，管理平台、接口、优先级、数据源和循环设置状态，并恢复编辑任务的优先级。
- `components/SinkConfigFields/index.tsx`：任务结果写回模式、结果列和完成标记字段。
- `components/DownloadConfigFields/index.tsx`：视频下载批量、代理、领取和重试窗口配置。
- `hooks/useTaskMetadata.ts`：加载 Action Schema、数据表字段与视频分析可用模型，通过独立请求序号阻止过期响应覆盖当前选择；模型目录失败时保留准确错误并支持重试。
- `utils/taskForm.ts`：表单文本读取、参数映射序列化、优先级校验/序列化、编辑初值转换和包含视频分析模型覆盖的 `TaskPayload` 组装。

## 提升复用规则

- 仅任务表单使用的组件、Hook 和工具继续保留在本目录。
- 被任务模块多个兄弟组件复用时，先移动到 `tasks/_components` 下的中立局部目录，禁止兄弟组件反向引用 `TaskForm` 私有实现。
- 只有确认跨页面或跨业务模块真实复用后，才提升到 crawler 共享组件或 `src/utils`，并同步更新对应 README。
- 优先级选项来自 crawler wire type，默认值为 `normal`。

只有模型目录成功加载后才判断历史模型是否不可用；网络或服务错误会阻止保存并提供重试入口，避免把加载失败误报为模型已下线。

视频分析任务的评审路线只能由表单使用者显式选择：`R` 表示参考视频，`G` 表示生成视频，空值表示素材来源未知且仅评审 C。表单不得根据素材内容推断路线；切换为非 `video_analysis` 执行器时，提交载荷会移除 `review_route`，由后端清理分析配置。视频下载任务的配置直接映射后端 `VideoDownloadTaskConfig`，编辑旧任务时使用后端默认值兜底。
