# 06｜发布数据诊断与单变量迭代

真实数据层用于解释发布表现，不并入 C \+ R 或 C \+ G 的 100 分。数据只能在可比背景下判断，不能用全平台统一死阈值。

# 1\. 必录数据字段

|阶段|字段|
|---|---|
|停留|2 秒留存、3 秒留存|
|观看|平均观看时长、平均观看比例、完播率、重播率|
|行为|商品点击率、加购率|
|转化|CVR、ROAS|
|定性反馈|评论内容质量|
|采集背景|发布时间、采集时间、自然流/付费流、样本量和数据来源|

样本量、观察窗口、数据源和数据冻结规则属于治理补充项；记录这些字段不会改变原稿分值。

# 2\. 可比性原则

优先在以下条件相近时比较：

- 同账号

- 同产品

- 同市场

- 同流量类型

- 相近发布时间

- 同类视频中位数

账号体量、价格、市场、投放方式和发布时间不同，都会造成数据偏差。

# 3\. 数据诊断关系

|观察结果|优先诊断|
|---|---|
|留存高、点击低|钩子强，但商品识别或购买理由弱|
|留存低、点击高|目标用户有需求，但开头拖慢|
|点击高、成交低|价格、详情页、尺码或信任存在问题|
|完播高、成交低|视频好看，但娱乐元素抢走商品|
|播放高、商品评论少|背景或模特可能成为主要记忆点|
|播放一般、点击转化高|更适合投放，不一定适合追求自然爆款|

以上是诊断关系，不是单因果证明；必须回到逐秒证据和商品/页面背景复核。

# 4\. 主要根因分类

- 创意策略

- 商品证据不足

- 首帧错误或与产品冲突

- 视频提示词错误

- 参考图排序或职责错误

- 模型能力边界

- 后期处理问题

低分或硬失败必须选择一个主要根因，同时可记录次要症状，但不能把所有问题混成一个修改包。

# 5\. 单变量迭代

1. 选择一个主要根因。

2. 只定义一个主要修改变量。

3. 写明预期改善的评分维度。

4. 指定验收时间码。

5. 写明可观察的成功标准。

6. 预先定义失败后的下一决策。

|字段|填写要求|
|---|---|
|修改内容|本轮唯一主要变量及具体改法|
|预期改善|对应 C、R、G 的哪个维度或哪个 G0|
|验收时间码|变化必须出现在哪一段|
|成功标准|可见、可测、可判定|
|失败后决策|保留、回退、换策略、换素材或换模型|

同一根因连续失败两次时，应更换策略、素材或模型，不继续堆砌同义词。若同时存在多个 G0 或合规风险，“只改一个变量”的例外规则尚待 Owner 明确。

# 6\. 发布后复盘输出

* [ ] 数据采集时间和流量类型明确

* [ ] 选择了可比基准，而非全平台死阈值

* [ ] 数据结论与 C/R/G 分数分开呈现

* [ ] 诊断回到时间码和商品证据复核

* [ ] 根因唯一，下一轮变量唯一且成功标准清楚
