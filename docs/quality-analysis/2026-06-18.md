## 6. 代码质量与已知问题

> 以下问题通过 codegraph AST 分析和 GitNexus 知识图谱系统性发现。

### 6.1 安全问题

| 编号 | 严重度 | 位置 | 问题描述 |
|------|--------|------|---------|
| **S-01** | **HIGH** | `http_server.go:58` | WebSocket `CheckOrigin` 返回 `true`，接受任意来源连接，存在 CSRF/WebSocket 劫持风险。而 `websocket.go:64` 使用更严格的 `sameOriginOrNoOrigin`，两个入口策略不一致 |
| **S-02** | **HIGH** | `cors.go:38-40` | `isOriginAllowed` 空白名单返回 `true`，默认允许所有 Origin 跨域访问 |
| **S-03** | **MEDIUM** | `auth.go:98` | Auth Token 通过 URL query 参数 (`c.Query("sekiro_token")`) 传递，token 会出现在访问日志、代理日志和浏览器历史中 |
| **S-04** | **MEDIUM** | `main.go:496-520` | WebSocket 注册端点 `/business/register` 对匿名分组无鉴权，任何人可接入 |
| **S-05** | **LOW** | `main.go:487-494` | `negotiateSubprotocol` 将客户端请求的 `Sec-WebSocket-Protocol` 原样回写，未做过滤 |

### 6.2 并发 / 正确性问题

| 编号 | 严重度 | 位置 | 问题描述 |
|------|--------|------|---------|
| **C-01** | **HIGH** | `sdk/client.go:133-158` | **BUG**: `handleDisconnect()` 先将 `c.Connection = nil`，再调 `notifyDisconnect()`。但 `notifyDisconnect` 检查 `c.Connection == nil` 就 return，导致 `respWaiters` 永远不被清理，等待响应的 goroutine 只能等到超时而非立即失败 |
| **C-02** | **MEDIUM** | `forwarder/timeout.go:83-100` | `StreamRecord.Push` 在持有 `r.mu` 锁的同时执行可能阻塞 5 秒的 channel send，期间同一 record 的 `Close`、`SetTimedOut` 等操作全部阻塞 |
| **C-03** | **MEDIUM** | `http_server.go:79-81` | `server.Serve(ln)` 错误被 `_ =` 忽略，端口被占用等服务启动失败时外部无法感知 |
| **C-04** | **MEDIUM** | `http_server.go:93` | `Shutdown()` 使用 `context.Background()` 无超时限制，长连接可能导致永久阻塞 |
| **C-05** | **LOW** | `flow/ratelimit.go:34-51` | `NewRateLimiter()` 启动的后台清理 goroutine 无 `stopChan`，中间件重建时泄漏 goroutine |

### 6.3 技术债

| 编号 | 位置 | 问题描述 |
|------|------|---------|
| **T-01** | `sdk/client.go:214-216` | `Register()` 方法空实现 `_ = handler`，调用者注册处理器后实际上什么都不会发生 |
| **T-02** | `database.go:115` | `ResetMetricTables` / `AutoMigrate` 混用 `log.Printf` / `log.Println` 和项目 `logger`，违反项目日志规范 |
| **T-03** | `invoke.go:650-685` | `filterAccessibleGroups` 重复鉴权逻辑：重新提取 token 查询用户，忽略中间件已在 context 设置的 `*model.UserInfo` |
| **T-04** | `sdk/invoker.go:228-236` | 自定义 `parseInt` 函数不处理负数和溢出，标准库 `strconv.Atoi` 更安全 |
| **T-05** | 全局 | 大量核心模块无测试覆盖（详见 6.4） |
